## 交付行为

| Before | After | Why |
| --- | --- | --- |
| 段落菜单出现带白底和箭头的系统滚动条，App 内联样式只覆盖显式标注区域 | 公共 CSS 覆盖应用及 portal 弹层中的滚动区域，细圆滑块、透明轨道/角落、隐藏箭头，适配深色与强制色彩 | 让菜单、文档、表格/代码、聊天、设置、任务和外层面板遵循同一规则，减少遗漏 |

| 纯文本中的错误标记只能由用户自行发现 | 停止输入 350ms 后检查常见可识别问题，右上角出现黄色警告图标，点击查看行号与线索 | 不打断输入，不把合法扩展语法直接判成损坏 |

模式图标保持固定尺寸，正文不因悬停而移动。warning popover 使用既有 AnchoredPopover、IconButton 和 Button。段落菜单仍可滚动访问底部删除操作，保留刻意隐藏的标签条滚动条以及 composer 的独立尺寸规则。只读保护的扩展语法文档仍可切源码。

## 检测与修复契约

- 检测覆盖常见未闭合代码围栏、行内反引号、双星号/双下划线/删除线标记、链接/图片地址括号和表格列数。识别围栏代码、缩进代码、行内代码、转义、frontmatter 等，避免把示例直接当故障。行号从 1 开始，最多展示 8 条。
- Markdown 允许多种写法，“疑似问题”不是语法错误的确定结论。检查不覆盖全部方言、单星号歧义、HTML/YAML/数学语法或语义排版质量。512K UTF-16 code units 以上文件不做这项同步检查。没有警告不保证文档无误。
- 检测从不触发写盘或模型调用。可取消修复；没有可用模型或已有文件冲突时，入口明确说明原因并禁用发送。
- 发送前使用原保存动作写入当前源码及 `expected_hash`。再次核对路径、正文、已保存版本、当前对话及模型；保存失败、版本变化、切换目标或冲突均停止请求。不可通过格式修复绕过“保留本地/重新加载”的冲突选择。
- 使用现有 override 消息入口，聊天输入草稿、附件与手动引用不会被清空或混入修复请求。Agent 忙碌时复用现有后续消息队列；请求进度和模型/网络错误仍显示在聊天区。
- 专用提示词明确唯一 JSON 引用路径、已保存哈希、疑似问题行号；先 `read_workspace_text`、最小化 `apply_workspace_patch`、修改后重读核对。不把全文嵌入提示；要求保留语义、顺序、术语、数值、URL、代码、frontmatter 与扩展语法。版本变化时重新检查，合法写法不强改，意图不明先询问。要求只修改目标文件，不为排版执行命令或外部调用。
- 这是一项交给当前 Agent 的修复请求，不是前端确定性格式化器；修复质量取决于模型和工具执行，界面不会只因发送请求就宣称文件已修好。

## 运行与恢复

- 新增 `internal/runqueue`，聊天和后台任务共享准入管理。默认最多 2 个运行、64 个已接纳任务；同一用户的 Agent 任务串行。容量包含运行和等待，额外请求返回明确失败。
- 排队任务可以直接取消；运行任务传递 context 取消信号。停机停止准入并等待回收；启动时立即核对上次遗留运行，修复快速重启两分钟内的空档。
- 终态不能被迟到更新覆盖；并发恢复只允许一次。上次执行尚在回收时拒绝立即恢复，防止两个执行代次争用同一个 run。
- 恢复时核对持久工具账本。未确认的写入、命令或技能副作用不再盲目重试；命令已完成但尚未进入检查点也会要求人工核验。成功文件修改可重建去重记录，未进入检查点的结果需要核验当前磁盘内容。
- 检查点缺失与读取失败、损坏 JSON 分开处理；后两者阻止从头执行。
- `/api/ready` 检查数据库连通性与调度器是否接纳工作，`/api/health` 保留进程存活用途。

队列是单进程设施，同一数据库和工作区根目录仅支持一个服务实例。它串行化 Agent 工作，不会锁住人工编辑器、外部命令或其他程序。内存等待队列本身不跨重启自动执行；聊天任务转为可恢复，后台任务沿用原有重排机制。

## 文件变更与事件

- 补丁拆分为规划、提交和回滚三项职责。每个文件记录 operation、内容哈希、版本、移动源路径或回收站恢复路径。
- 验证覆盖所有新增、修改、移动和删除，不再把任意一个文件可读等同于整个补丁通过。编辑器按具体路径取对应版本和哈希。
- 回滚错误汇总返回；恢复旧内容和删除刚创建文件前均核对当前哈希。回滚不受原请求取消打断，但仍是尽力恢复。
- SSE 先订阅再读历史，按数据库序号发送。内存 broker 只承担唤醒；每次通知与心跳补读持久事件，处理乱序通知和缓冲区溢出。
- `chatRunTransport.js` 统一管理 EventSource、重连计时器、顺序投递和取消。无效 JSON 或事件处理失败终止后续投递，结束时清理连接；加载计时器由调用方 finally 回收。
- 工具契约回归检查管理员/普通用户下两协议 schema 一致、manifest 存在、执行分发存在。完整 ToolSpec 类型生成尚未实施。

命令取消在 Unix 使用独立进程组，Windows 使用系统 taskkill 终止普通后代进程；这不是安全隔离，也不能保证主动脱离的进程被回收。

## 动画检查

| Before | After | Why |
|---|---|---|
| 面板宽度过渡、FLIP 和内容入场同时执行，最长 900ms | 布局立即确定，由单一可取消的位移/淡入处理空间变化 | 避免多套动画争抢几何与连续操作残留 |
| render 内修改入场集合并创建 timeout | 动画资源由 effect 管理，结束/替换/卸载都清理 | 保持 React render 纯净，避免竞态 |
| 焦点光效 portal 每帧测量位置 | 焦点边界附着面板，由 CSS 过渡 | 避免错位、反复测量与光效残留 |
| 菜单动画固定从上方展开，尺寸被 transform 影响 | 按实际弹出方向设置原点，使用布局尺寸定位 | 菜单贴合触发点，减少弹跳 |
| 多种硬编码时长和 JS 动画忽略 reduced motion | 共享动效节奏与偏好，减少动态效果时直接完成位置变化 | 高频交互更快，辅助功能一致 |
| 拖拽开始计时器、resize 监听与失效的“最近添加”状态分散存在 | 拖拽计时器可撤销，resize 监听在卸载时清理，删除未使用状态 | 防止操作结束或卸载后遗留回调 |

共享节奏：退出 120ms、控件 160ms、菜单/消息 180ms、设置窗口 220ms、布局 240ms。面板采用立即布局和单一可取消的位移/透明度动画；设置子卡片不再重复 stagger 入场。保留原视觉语言，整理动画机制与连续操作表现。

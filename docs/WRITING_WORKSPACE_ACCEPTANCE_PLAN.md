最终验收口径（用户补充）：评估 Perseus 的功能、工具契约、存储、交互和恢复；文风、推理、长度及事实选择等纯模型能力不作为工作台失败。若模型未触发某功能，则补一个明确指令验证，仍无法触发时记未覆盖，不能当作通过。正文在模型原始输出、工具参数、落盘与界面之间被工作台丢失或错误转换，仍属于产品问题。下文写作内容约束用于提供真实操作场景，不作为模型智力考试。

## 产品与执行定位

Perseus 是部署在服务器、通过浏览器使用的文稿工作台。测试对象为其服务器工作区中的文稿，不要求访问用户电脑的本地项目，不要求写代码、运行命令、安装依赖或使用 Skill。

按用户指定使用 http://127.0.0.1:8080/ 的现有实例。测试前记录现有状态、确认没有其他运行任务并备份数据库和用户目录；全部测试稿件放进唯一的 `验收测试/阅读活动-<批次>/`，使用专用会话。现有稿件、会话、默认模型和凭据不修改。测试外文件按哈希核对，测试结束保留测试稿件供用户检查。

本轮目标是通过真实文稿工作发现问题，交付证据和问题清单，不在测试过程中自动修复产品代码。预计约 2–3 小时，最多 4 小时或 100 次真实模型出站请求（含重试与辅助请求），到限保留结果并列出未执行项，不为凑时长生成冗余稿件。

## 测试场景：秋季阅读活动文稿包

这是虚构活动资料，用来测试信息核对和多稿协同，不是新产品，也不是给 Perseus 增加功能。活动名称为“把秋天读进生活”，场地“青禾书屋”为测试虚构地点，不对外发布。

准备五份有意存在少量冲突的资料和一份附件：

| 资料 | 核心事实或用途 |
| --- | --- |
| `原始资料/最终确认单.md` | 唯一最高优先级：2026-11-15，14:00–16:00，青禾书屋二层；免费；名额 40；报名截止 2026-11-12 18:00；不设置真实报名链接和电话 |
| `原始资料/早期方案.md` | 旧版本写名额 30、截止 11-10；Agent 应识别冲突，不能混入最终稿 |
| `原始资料/会议纪要.md` | 面向成年普通读者；携带一本愿意交流的书；不承诺赠品；包含相近段落，检验精确局部修订 |
| `原始资料/风格要求.md` | 温和清楚、避免夸张和虚构引语；时间统一 24 小时制；不编造嘉宾、赞助商和报名方式 |
| `原始资料/排版样稿.md` | 标题、表格、任务列表、嵌套列表、代码围栏和现有扩展语法，用于编辑器检验，不要求执行代码 |
| 上传附件 `补充要求.txt` | 社交短文正文 140–200 个可见 Unicode 字符；统计正文，不含标题、空格和换行；要求注明资料来源 |

额外放入 `请勿修改/原始记录.txt` 哨兵，并保存全部原始资料的哈希。资料可读，原件不改，成果另存。验证器的事实表和长度计算规则在模型执行前固定，不能从生成结果推导答案。

## 发给 Agent 的首条指令

```text
请为测试活动“把秋天读进生活”制作一套可交付的文稿。所有资料和输出仅限这次指定的测试目录，现有其他稿件不要修改。

先阅读原始资料及上传附件。资料冲突以最终确认单为准，列出冲突与处理依据；信息缺失不能编造。请先询问我：活动介绍应偏“温和叙述”还是“简洁公告”，等我回答后再继续写。

完成以下稿件，分别保存成 Markdown 文件：
1. 资料核对表：列出最终事实、来源、冲突和缺失信息。
2. 活动介绍：正文 600–900 个可见 Unicode 字符，不计标题、空格和换行。
3. 社交短文：正文 140–200 个可见 Unicode 字符，不计标题、空格和换行。
4. 报名 FAQ：至少 8 组问答，缺失信息明确写待确认，不编造报名渠道。
5. 主持人流程稿：时间表和开场、过渡、结束串词；不虚构嘉宾。
6. 交付清单：链接到以上稿件，逐项说明事实、长度、完成状态和待确认项。

保留原始资料。生成之后自行重读，核对跨稿一致性、数字、时间、长度和 Markdown 格式。实际保存文件后才能说已完成，不要只在聊天中输出全文。如果有不能完成的要求，请明确说明。
```

回答语气问题时选择“温和叙述”。首条指令不透露后续修改，以检验真实多轮编辑。

## 8080 上的可控异常

| 编号 | 操作 | 核验重点 |
| --- | --- | --- |
| E01 浏览器重连 | 写稿中刷新测试页面，或短暂阻断本测试页的事件流后恢复 | 运行结果能补齐，消息不重复，已成功写入不因刷新重复执行 |
| E02 停止 | 独立测试轮次写多个测试片段，活动中点停止，等服务端确认 | 终态一致；确认取消后不再启动新的写工具；确认前已发生的变更有明确说明 |
| E03 保存冲突 | 浏览器有未保存修订时，测试驱动对同一测试文件写入另一标记 | 不静默覆盖两边内容；明确提示冲突；格式修复在保存失败时不发送 |
| E04 旧内容失配 | 让工具准备修改时由驱动更新同一测试段落，再允许提交 | 不强行用模糊匹配改错段落，保留后改内容，有明确失败或重读 |
| E05 多会话 | A 写稿时切到 B，输入独立草稿，再返回 A | A 的流式事件不污染 B；两会话草稿、补充输入和恢复提示身份正确 |

异常只作用于本次测试会话和文件。不在共享 8080 注入数据库损坏/存储 trigger、杀服务、替换供应商或启用宿主命令；这些属于另行隔离的可靠性验收，本轮标记未测，不算通过。

## 证据、归因和交付

每项记录 PASS / FAIL / BLOCKED / NOT RUN，并保存必要截图、脱敏事件、运行 ID、文件前后差异和首次失败。关键局部编辑、保存冲突、跨会话场景用副本复测一次，不以重试成功抹掉首错。

事实、数字和长度用预先固定规则独立核对；文风和可读性人工审读，两类结论分开。记录工具、前端、后端、模型未遵守要求及外部条件等具体原因，不能只说“模型问题”。

出现测试目录外意外写入、用户内容丢失、停止不生效或持续无界请求时，立即停止相关测试，保留证据；不未经核对用备份覆盖当前数据库，因为可能包含测试期间用户新增内容。

交付 `docs/WRITING_WORKSPACE_ACCEPTANCE_RESULTS.md` 及 `_local_artifacts/writing-acceptance/<批次>/` 证据，给出通过范围、最小复现、影响和修复优先级。8080 测试不等于云部署验收，云端反向代理、HTTPS、存储卷和重启恢复若未实际部署验证需列为未测。

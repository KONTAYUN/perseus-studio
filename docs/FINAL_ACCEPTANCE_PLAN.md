## 1. 测什么、如何得出结论

Perseus 按服务器文稿工作台验收：资料上传、聊天协作、文稿生成、精确修订、人工排版、保存与恢复、后台任务及交付。不将其当成本地编码 Agent，不安装 Skill，不开启宿主命令，不评价模型的文风和智力。Skill 只检查未配置时的空状态/提示，不将真实调用列入本次已承诺范围。

分三条测试线：

| 测试线 | 环境与作用 | 数据规则 |
| --- | --- | --- |
| 真实使用 | 8080、现有可用模型、真实浏览器；检验用户从资料到交付的完整链路 | 唯一测试目录和专用会话；保留原稿、原会话、原模型及默认配置 |
| 确定性验证 | 独立端口、数据库、用户目录、本地可控供应商；补齐正常模型不一定触发的边界、时序和错误 | 注册/封禁/删用户、改配置、永久删除、重启、强杀、写库失败等全部在这里做；禁止误连 8080 |
| 云端验收 | 实际拟部署的 Linux/容器、HTTPS/反向代理与持久卷环境 | 单独测试空间或预发布副本；没有环境就记未覆盖，不以 Windows 本地结果代替 |

共 **90 个计划用例：84 个本地用例、6 个云端用例**。一个用例可能有多个子场景，子场景分别留证；这不是已存在的自动测试数量，也不是全绿承诺。

执行顺序：锁定基线及备份 → 自动回归/构建 → 真实完整流程 → 配置与权限 → 隔离故障/恢复 → 90 分钟持续运行 → 云端（如具备环境）→ 数据终检与报告。每阶段先完成证据核对再进入下一阶段。

估计本地约 4–6 小时，云端另约 1–2 小时；这只是安排，不当作实际执行时长。真实模型请求以 **200 次可观察出站尝试**为本轮看护上限，计入已观察到的工具轮次、重试、标题与压缩请求；接近上限先收尾，不用用户消息数代替请求数。总本地执行到 8 小时仍有缺口时，交付已完成结果和剩余项。模拟供应商不消耗真实模型额度。计量存在缺口时明确披露，不声称精确总账或硬性金额封顶。

## 3. 一条贯穿全程的真实文稿任务

场景为虚构“社区阅读月”，不是新项目或新产品。目录 `验收测试/最终验收-<批次>/`；会话主线 A、对照 B、恢复 C、后台 D；以唯一批次隔离本轮和历史测试。

准备：最终确认单、旧方案、会议纪要、风格要求、排版样稿、UTF-8 文本附件、不可修改哨兵。固定事实为 2026-11-21 14:00–16:00、青禾书屋二层、40 人、免费；报名方式/嘉宾未确认。后续只把地点改为一层、人数改为 36。原始资料保留旧事实，更新依据记入变更说明。

| 步骤 | 给 Agent 的要求 / 人工操作 | 必须看见的实际行为 |
| --- | --- | --- |
| 1 | 上传资料、附加文本；要求先读、列冲突并询问文稿语气，收到回答前不写 | 附件身份及纳入上下文状态真实；读取和提问均有记录，回答后继续正确会话 |
| 2 | 生成活动介绍、FAQ、主持流程、短通知、事实核对表、交付清单六份文稿；保存并回读 | 六份非空文件真实落盘，工具结果、编辑器和最终回复一致 |
| 3 | 地点/名额统一更新；只改指定段落或 FAQ 一问，其余内容不动 | 多稿变更可核对，非目标段落及哨兵保持；不以全文重写掩盖错改 |
| 4 | 运行中排队一条跟进，刷新；另轮替换/删除待发项；使用真正的补充指令 | 排队和 steer 身份分明，刷新不丢、只消费一次，已删除内容不执行 |
| 5 | 在另一会话留草稿；返回主线压缩、分支、重新生成 | 不串会话；压缩结果/失败不吞草稿；分支和原历史可区分 |
| 6 | 两编辑栏打开不同稿件；人工改格式、保存；Agent 再改稿；制造本地/服务端冲突 | 正确文件上下文，人工内容不被静默覆盖；显式解决冲突后才覆盖 |
| 7 | 阅读代码块并复制；选区工具条和段落六点菜单排版；源码/富文本往返 | 复制内容准确、格式可保存；打开或单纯切换模式不写盘 |
| 8 | 在副本制造格式问题；先取消修复，再确认让当前 Agent 修复 | 取消不发消息；确认指向正确稿件；原输入草稿保留，保存失败不发修复消息 |
| 9 | 专用任务执行中停止，确认终止后继续；在隔离环境补足所有竞态 | 停止后不启动新工具；在途动作单独核对；继续不重复已确认副作用 |
| 10 | 后台交叉核对、保存报告；另一后台任务取消；刷新重读追踪记录 | 前台完成事件和 task_id 完整，后台正文/工具/终态可回读，无假成功 |
| 11 | 重命名、移动、删除测试副本、恢复，核对打开标签与剩余稿件 | 路径、标签、磁盘一致；回收站数据可恢复，原文件不受影响 |
| 12 | 只读核验交付包，列完成/未完成/待确认项，下载测试成果 | 下载与落盘一致；所有保存声明有证据，遗漏如实呈现，结束后无悬挂任务 |

这一主线覆盖下表多个用例，不重复计数。模型未触发目标工具时可追加一次明确指令；仍未触发则记未覆盖，再用确定性测试验证平台分支，不能冒充真实模型通过。

## 5. 每条回复和后台执行的审阅规则

所有可观察助手正文、提问、进度文字、错误说明、终态替换片段、后台 model_response_observed、完成预览和最终消息都入清单并逐条审读。流式 token 先重组；重复保存的同一正文建立对应关系，不按每个 token 或重复事件膨胀“回复数量”。不要求或声称检查模型未公开的内部推理。

每条审阅记录包含：当前要求；会话/run/task/execution/message 身份；完整正文及撤回关系；是否新获信息/产生进展；声称读写/完成/失败对应的工具和落盘证据；正常/合理等待/已恢复异常/疑似绕圈/声明不实/证据不足结论。首次错误和后续恢复都保留，不只给最后成功截图。

后台交叉核验链：用户操作 → 受理/待发/steer 身份 → run/task → 供应商尝试 → 工具参数/结果/副作用 → 文件版本 → 最终消息/outcome → 完成事件/检查点。事件超页时用游标全量读取，UI 正常不等于后台账本正常。

不靠“失败”“完成”等关键词判错。相同动作重复是否合理，要对照文件版本、参数、返回结果和进展。连续三次等价无进展动作触发调查；连续五分钟无新文本、工具结果、文件变化或可解释等待时保留现场、检查并决定取消。这是测试看护规则，不新增产品阈值，也不把合理退避/等待回答算死循环。

## 6. 数据保护、故障处置和通过门槛

测试前在线一致性备份数据库；用户目录在无运行/写入时复制并核对前后摘要。原用户数据只读留档，密钥和登录态仅保留本地私有证据，报告脱敏。备份恢复、临时账号删除、永久清空、故障注入仅在核对身份的副本执行。恢复副本首次启动前隔离真实供应商，避免复制的任务或配置意外发起付费请求。

现有表的原行逐行/多重集摘要核对，文件按摘要核对；本轮合法测试增量单列。若用户同期有正常操作，保留其变化并单独说明，不能为“摘要一致”回滚用户新内容。开始/结束记录全部表清单，重点包括用户/模型/搜索配置、会话/消息、运行/任务/待发、工具/事件/变更台账；会自然增长的会话/用量按预期增量核对。

发现目录外非预期修改、数据丢失、越权、秘密暴露、取消终态后新副作用、无界请求或无法停止的任务时，立即停止相关阶段、保护现场；不自动恢复旧库覆盖现库。普通 UI 故障先记录再继续无依赖项，不能为了表面全绿反复改提示词重试。测试驱动错误单独归因并重测，首次证据不删。

每个用例及子场景分别标 **PASS / FAIL / BLOCKED / NOT COVERED / N/A**；N/A 只能用于经确认不属于当前产品的功能，不能把“没有测试条件”改标 N/A。归因为平台、外部服务/网络、模型表现、测试驱动或证据不足。模型智力不评分；合法工具被平台误处理、上下文丢失、错误结果被隐藏、无界执行或假成功仍是平台问题。

通过门槛：

- 本轮实际构建的自动回归/构建/静态门禁通过，全部跳过和未覆盖可解释。
- 核心读写、保存冲突、取消/恢复、排队、用户隔离、前后台终态、数据保护必须通过；未审完全部可观察回复，不能声称“逐条审阅通过”。
- 无未解决的数据完整性、越权/凭据泄露、不可控执行及核心功能阻断缺陷；任何这类缺陷阻止对应交付范围通过。
- 其他缺陷逐项给严重性、复现、影响、规避方式及修复建议；未关闭项须用户明确接受，不能靠“低优先级”自动视为通过。
- 云端项无环境时只能交付“本地功能验收结果”，不能下“云端可正式上线”的结论。即使全部通过，也只说明指定环境/构建/场景的结果，不承诺零缺陷。

本轮按批准基线测试和报告，不边测边无记录地改产品。若发现问题需要修复，先保留失败证据；修复后产生新构建身份，重测失败项和受影响功能，再决定是否需要新一轮全套。保持首次失败与修复后复测可区分。

## 修改

### AC-01：统一编辑契约

后台执行、产物补做和两种供应商协议的补丁 schema 现在共用 `ai.WorkspacePatchExecutionRule`：必须调用结构化 `apply_workspace_patch`，将完整补丁放在 `patch` 参数；正文及代码围栏仅展示，不执行。删除“直接输出补丁会执行”的旧说明，补做提示要求写后回读。补丁诊断中的 transport 同步改为 JSON。

没有恢复正文解析执行，也没有通过匹配模型回复关键词来猜测是否需要修改文件。已有严格补丁匹配、权限和完成校验继续生效。

### AC-02：后台失败记录执行模型快照

模型解析成功时，通过类型明确的回调保存 provider ID、名称、model ID、协议。后台首次执行和每次补做分别记录本次选择，在工具/供应商失败、产物耗尽、消息或终态落库失败时，失败诊断带上这份快照及来源消息、任务和会话 ID。

回调的数据结构没有密钥或连接地址。失败后不重新查找当前默认模型，避免运行中修改或删除配置导致误归属。模型尚未解析成功时保留请求的 provider ID，不编造模型名称。历史失败记录保持原样，本次不回填猜测信息。

### AC-03：按实际状态显示工具文案

- 参数验证拒绝、调用预算耗尽或执行账本尚未建立：显示“工具未执行”。
- 执行器确实报错：显示“工具执行失败”。
- 命令已经启动时，依据结构化 execution_outcome 分别显示失败、超时、取消、结果待核对；成功仍显示“已运行命令”。

UI 附件与持久事件使用相同标签。没有改变命令的权限或启用策略，8080 的宿主命令仍关闭。

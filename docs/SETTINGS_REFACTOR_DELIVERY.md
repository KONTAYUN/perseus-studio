## 实施范围

按 [设置设计评审](SETTINGS_DESIGN_REVIEW.md) 实施分类导航、列表与编辑分离、保存反馈和误操作保护。保留现有字体、蓝色强调、浅深主题、圆角及共享控件。无需新增路由框架或第三方组件库。

| 之前 | 现在 | 原因 |
| --- | --- | --- |
| 各类配置和常驻表单混在长弹窗 | 六类设置，稳定侧栏，默认进入模型列表 | 更容易找到当前任务 |
| 模型信息旁一直显示窄表单 | 先看列表，再添加或编辑；单列表单 | 减少干扰，留出字段宽度 |
| 思考、上下文、兼容参数与基础连接混排 | 基础连接在前，高级设置按需展开 | 保留功能，降低首次配置负担 |
| 全局“完成”只关闭，不表示保存 | 表单明确保存／取消，错误在当前页面显示 | 让保存结果可判断 |
| 离开会丢失配置草稿 | 离开确认、提交锁、刷新保护 | 避免误丢输入或重复创建 |
| 价格配置套在第二层大弹窗 | 同一内容区域的价格列表／编辑页 | 简化返回路径 |
| 手机仍依赖桌面长布局 | 手机分类选择器、表单换行、可达的操作栏 | 保持核心操作可用 |

设置分类：模型与连接、联网搜索、工具扩展、用户与访问、用量与费用、诊断日志。用户创建与列表分开，用户管理和清空日志的次要／危险操作集中在可读的操作菜单内。

## 状态及数据契约

- `App` 保持工作台组件挂载；设置显示时隐藏并隔离工作台交互，返回时恢复触发位置。编辑器草稿、聊天草稿和 Agent 事件流不因进入设置而重新初始化。
- `SettingsWorkspace` 只负责导航与内容外壳；`SettingsNavigation` 统一处理离开确认和提交期阻止离开。`useSettingsEditor` 管理配置草稿、基线、编辑对象、提交锁和反馈，各设置页面注册自己的完整离开条件。
- 模型和搜索保留现有后端配置结构。每个模型独立保存；没有按相同 URL 推断或合并密钥。编辑密钥留空继续保留后端原值。
- 获取模型、测试调用和保存分别操作；测试说明会调用模型并可能产生用量。一次获取仍支持逐行“＋”连续添加，已添加反馈保留，并可搜索结果。
- 写入成功与列表刷新失败分开处理。刷新失败显示“已保存，请刷新列表，无需重复保存”，避免把已经成功的创建再提交一次。
- 测试报告绑定连接及 Model ID；修改关键参数后清除旧报告，并丢弃已失效请求的迟到结果。
- 确认／输入对话框补上初始焦点、Tab 循环、Escape、背景交互隔离和焦点返回。长列表底部菜单根据实际空间向上展开，长 ID 允许换行。

## 测试中发现并修复的问题

1. **空用量统计返回 500**：全新数据库或筛选无结果时，成功／失败次数的 SQL `SUM` 返回 NULL，扫描为整数失败，使费用页的模型列表也未加载。改为 SQL `COALESCE(..., 0)`。独立临时数据库回归覆盖全空、无匹配模型和无匹配用户，修复前失败记录保留在 `usage-empty-before.log`。
2. **放弃配置并返回后可能点不动工作台**：确认框关闭与设置关闭同时发生时，焦点 hook 恢复了设置原有的 `inert`，覆盖 React 已移除的状态。现在只恢复 hook 自己改动的节点；新增返回后没有残留 inert、按钮可点击的回归。
3. **小屏获取模型说明被挤成窄列**：说明与两个按钮竞争宽度；改为可换行分组，并检查 390 px 下说明宽度。
4. **长列表底部操作菜单越界及分隔行样式被通用卡片覆盖**：补上展开方向与高度限制，移除行级多余卡片类；增加 24 条长 ID 的桌面／手机回归。

测试适配也保留证据：旧模型发现测试依赖已移除的卡片样式类，改为稳定的配置 ID；无模型测试独立提供空列表；富文本行内测试改用实际鼠标选区并检查光标收起，减少程序生成选区与键盘事件的时序干扰。曾出现一次已有拖拽自包含提示测试失败，最终在全新隔离运行目录复核通过；没有因此修改拖拽产品实现，不能据此宣称既有拖拽时序问题已完全排除。前两轮失败的截图／trace 与日志均保留。

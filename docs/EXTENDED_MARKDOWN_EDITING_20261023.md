# 扩展 Markdown 可编辑性修复 — 2026-10-23

## 问题与决定

此前 `richEditingRestriction` 在发现文档头信息、HTML、脚注、数学标记、容器、Wiki 链接或引用定义时，会卸载整篇富文本编辑器，改为只读预览；超过 512 KiB 也会进入只读状态。用户必须理解并切换源码才能继续。这不是编辑失败后的合理出口。

本轮删除整篇编辑资格扫描，改为语法节点的局部保留。不会通过删除特殊内容、执行原始 HTML 或隐式调用 Agent 来解除限制。该机制取代上一轮表格报告中的“扩展文档使用只读预览”方案。

## 实现

- YAML/TOML 头信息、HTML 块/注释/声明、脚注、公式、容器使用惰性块节点；Wiki、行内公式、脚注引用、未知行内 HTML 使用惰性行内节点。
- 链接定义继续由 Markdown 词法器建立引用作用域，同时保留定义、完整/简写/折叠引用和引用图片的原始写法。
- 原始内容作为节点数据和文字展示，不注入 HTML、样式、事件或脚本。保留现有安全链接、受支持 span 和表格换行契约。
- 正文继续使用正常富文本编辑；特殊块提供复制、局部编辑、前后继续写。局部编辑支持取消、Escape、应用和正常撤销；选中整个块可复制、删除和撤销。
- 不再根据每次输入的全文匹配结果卸载编辑器，避免编辑回声导致焦点、输入和撤销记录丢失。外部文件替换仍重置旧撤销历史，既有哈希冲突处理保持有效。
- 纯文字剪贴板中的扩展 Markdown 使用同一解析入口；HTML 表格粘贴与应用自己的保留节点剪贴板继续走现有结构化路径。
- 长文档超过 128 KiB 或 1000 个换行时按根语法节点分段，一次挂载有限段落；支持上一段、下一段和直接跳转。未修改段落逐字保留，浏览/切段不会保存。
- 无法安全切开的超长单块或带全文引用作用域的长文档直接提供文字编辑，避免强行拆解结构或只读锁定。编辑器组件/资源加载异常也提供保留原文、接入同一保存流程的可编辑兜底。
- 清理旧资格扫描专用的无调用辅助代码。窄编辑栏说明与按钮自动换行，失焦后不展示默认节点选择框。

## 本轮复现并修正的边界

1. Markdown 扩展的块起点提示若匹配截断字符串的首字符，会把行内代码中的 HTML 当作块。现在只提示真实后续行，代码示例和自动链接保留原有可编辑类型。
2. 保留块点击后未选中节点，导致键盘复制为空；改为明确选择节点，并提供独立复制按钮。
3. 数量很多的短段落即使未到旧文件长度阈值，也可能产生过多编辑器节点。增加行数与每段根节点数上限；密集文稿专项验证通过。
4. 跨段引用不能独立解析；无法保持引用作用域时采用直接文字编辑，防止引用被转义而失效。
5. 容器中的围栏代码可能包含容器结束标记；识别结束边界时跳过代码围栏。覆盖嵌套容器、空格属性写法及 BOM 头信息。
6. 多行 HTML 标签的独立 `>` 行会被普通块解析器当作引用并丢失闭合字符；在块解析前保留完整多行标签。覆盖带事件属性的变体，仍不执行。

## 实际限制

局部保留不等于所有扩展都有原生所见即所得排版。复杂 HTML、公式、容器等在保留块中显示原始内容，局部编辑不提供对应语言的可视化设计器；用户可以继续编辑周围正文，无需先修复该块。单个超长结构及跨段引用文稿采用文字编辑兜底。

正常富文本编辑仍可能规范化普通 Markdown 的空白、列表标记和实体写法；保留节点的载荷、未编辑长文档分段及打开不写入具有独立回归。换行沿用文档原有约定，混合换行的被编辑段可能被统一。分段切换重新建立当前段的撤销历史，不提供跨段全局撤销。

本轮验证为 Windows 本地 Chrome，未新增其他浏览器、移动端真机或任意第三方 Markdown 插件兼容性保证。没有宣称零缺陷。

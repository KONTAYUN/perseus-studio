## 失败记录与对照

没有把初次测试失败抹成通过。原始脚本及日志保留，区别如下：

1. `fault.log` 中多用户用例最初要求所有跨用户读取必须返回 404；实际消息和事件接口对当前用户执行过滤，返回 200 空集合。核对实现后改为断言无 items、无 latest_run，并保留 run 资源的 404 断言。原脚本还误用了不存在的 `conversation_messages` 表名，实际为 `messages`。两项均为测试假设/驱动错误；纠正后在全新 `fault-verified/` 数据目录重新跑完 9 项，全部通过，产品未改。
2. `document.log`、`document-proof.json` 中，Playwright `locator.fill` 对约 216 KB、16000 行文本整篇替换超时；随后截图也超时。`large-diagnose.json` 在完全不加载 Perseus 的原生 textarea 上复现同一 fill 超时。因此不能据此确认是应用编辑逻辑故障。应用内正常键盘追加、保存和重开通过；改用实际剪贴板、Ctrl+A/Ctrl+V/Ctrl+S 的独立用例也通过（`large-paste.json`）。原失败保留为大文本 fill 路径的测试/浏览器限制，不计为产品通过用例。

## 仍未覆盖

- 多小时持续负载、大规模并发、内存长期趋势、磁盘打满和文件系统/设备真实 I/O 故障。
- Linux 原生运行、容器、真实 HTTPS 反向代理与云端网络切换；本轮进程强杀不等同于断电测试。
- 精确到生产转交指令某一条语句的进程崩溃窗口、后台任务完整 checkpoint/resume、多副本协调。
- 大型 WAL 数据库的在线一致性备份；本轮只验证空闲后停机复制。
- 真实供应商、搜索服务的此次联调及长对话语义能力；本轮用确定性端点测试平台机制。
- 更大或更复杂文稿在富文本模式的性能边界。本轮较大文稿页面用例验证的是纯文本编辑器，不据此宣称大富文本文档性能合格。

# 设置页面设计评审（2026-10-23）

## 结论与范围

建议重构设置的导航、内容组织和编辑流程，保留现有浅色／深色、蓝色强调、半透明表面、圆角、字体及共享控件体系。仅调整间距和缩小卡片无法解决当前任务混杂、表单常驻、保存含义不清的问题。

推荐做应用内的独立设置视图：左侧稳定分类导航，右侧只显示当前类别；设置内的长表单使用页内详情，短确认仍使用对话框。此处“独立”指视图职责，不要求另建服务、重写后端或引入路由框架。工作台的编辑器、会话、草稿和运行状态在切换前后必须保留。

本文保留重构前的设计研究与只读评审基线。用户随后授权实施，现已完成重构、故障回归与 8080 交接，实际功能、测试证据和剩余边界见 [SETTINGS_REFACTOR_DELIVERY.md](SETTINGS_REFACTOR_DELIVERY.md)。以下“当前”观察均指改造前。

## 实际观察

当前登录为管理员，在 1292×1036 浏览器窗口、一个模型配置和一个搜索工具的条件下：

- 设置正文可见高度 744 px，滚动总高度 2603 px，约为 3.5 个可见区域。后续模型数量增加会继续拉长页面。
- 初始页面包含 6 个业务分区、27 个按钮；模型编辑区宽 380 px、高 987 px，尚未展开高级选项。
- 页面前两块是用户管理和当前为空的 Skills；模型配置在第三块。模型和搜索的空白新增表单始终展示。
- 打开后焦点留在背景“设置”按钮，按一次 Tab，实际焦点进入背景“退出登录”。本次只移动焦点，没有触发退出。页面声明了 aria-modal，却未真正约束焦点。
- 点击模型“编辑”只在原位置替换右侧表单内容，焦点仍在列表编辑按钮；没有独立编辑上下文。宽屏列表侧留白与窄长表单同时存在。

以上为本次环境观察，不是所有屏幕／账户的性能或可用性统计。默认进入模型页是根据配置任务及当前页面结构作出的产品建议，尚无真实使用频次数据。

## 当前与建议

| Before | After | Why |
| --- | --- | --- |
| “偏好设置”混合配置、用户、统计、日志 | 命名“工作台设置”，明确管理员范围；配置与系统管理分组 | 用户能先理解这里控制什么 |
| 六块内容共用一个长滚动页面，部分又跳子视图 | 稳定分类导航＋每类独立内容 | 位置可预测，不必滚动寻找入口或返回首页再换类别 |
| 用户管理和空 Skills 抢占第一屏 | 默认模型页，工具扩展后置 | 先完成文稿工作台可用所需的配置 |
| 列表和新增表单始终并排，表单只有 380 px | 列表浏览与添加／编辑分开；只在请求编辑时显示单列表单 | 消除空表单和大片留白，为长 URL、模型名和说明留空间 |
| 名称、可见性、Model ID 排在连接凭据之前 | 先协议／服务地址／密钥，再获取模型或手工填写 Model ID，最后设置名称与可见性 | 与“接入服务→选择模型”的实际任务顺序一致 |
| 获取列表、填入表单、直接加号、底部添加、测试混在一起 | 保留逐项加号；明确“＋立即添加”，手工配置为另一条入口；测试说明作用范围 | 不改变既有连续添加能力，减少保存含义冲突 |
| “完成”仅关闭，但表单另有保存；重置也可能丢弃编辑 | 表单底部“取消／保存模型”；离开时检查未保存输入 | 不让用户把关闭误认为保存 |
| 全局错误出现在长页面顶部 | 字段错误紧邻字段，请求失败出现在当前表单；保存和刷新结果分别说明 | 错误可见、可处理，避免保存成功却误以为失败后重复添加 |
| 每张卡片叠加背景、标题、说明与内部卡片 | 分类用导航，分组用标题和留白，列表用行与分隔线 | 保留材质风格，但减少无信息作用的容器层级 |
| 模态只声明角色，焦点可进入背景 | 独立设置视图有清晰焦点入口；剩余对话框实现初始焦点、焦点循环和关闭返回 | 视觉与键盘行为一致 |
| 搜索说明仍称“仅预留”，字段中英混用 | 依据实际能力说明联网搜索；Provider 改“服务商”、Priority 改“调用优先级”并解释 | 避免文案与已实现能力冲突 |

## 推荐信息架构

桌面保持工作台现有视觉语言，采用一个设置外壳。左侧导航建议约 200–220 px；右侧内容有明确页标题和一行必要说明。类别切换不叠加浮层，不播放重复卡片入场动画。

```text
工作台设置                                      返回工作台
┌─────────────────┬────────────────────────────────────┐
│ 工作台功能       │ 模型与连接                 添加模型 │
│   模型与连接     │ 搜索已配置模型                     │
│   联网搜索       │ 名称 / 模型 ID / 状态 / 可见范围     │
│   工具扩展       │ grok-4.7 …     编辑          更多 ⋯ │
│                 │                                    │
│ 系统管理         │                                    │
│   用户与访问     │                                    │
│   用量与费用     │                                    │
│   诊断日志       │                                    │
└─────────────────┴────────────────────────────────────┘
```

- “工具扩展”承载当前 Skills 功能，不增加新的扩展系统，也不因当前为空而抢占默认页。保留原有权限判断。
- “用户与访问”包含用户列表和注册规则；危险操作放入明确命名的菜单和确认流程，不与普通编辑图标混排。
- “用量与费用”内分统计与价格配置，保持筛选条件；避免为价格再叠加一整层大型模态。
- “诊断日志”作为查询页面展示筛选、列表、详情；复制／导出与清空分开，清空不与日常操作同级强调。
- 模型较少时使用紧凑列表，不强迫套复杂数据表；较多时提供搜索／状态筛选。首版无需为六个类别额外添加全局设置搜索。
- 低于约 760 px 时导航改为可识别的分类选择入口，内容单列；具体断点应按内容验收，不照搬设备名。
- 这些宽度、断点和默认入口属于项目方案，不是外部规范的强制值。

## 模型配置流程

### 查看和编辑已有模型

默认是已配置列表，显示用户可识别的名称、Model ID、协议、启用／默认／可见范围。凭据只显示“已配置”等摘要，原始密钥不进入列表。服务地址可在详情完整查看或复制。

点击“编辑”进入同页详情，标题包含被编辑模型名称。字段以单列为主，常规宽度约 600–720 px，不为填满空间硬拆双列。固定在表单底部的操作区域明确“取消／保存模型”，不提供一个冒充全局保存的“完成”。保存过程中按钮显示进度并防止重复提交；失败保留所有输入并在原处提示。

现有 `saveModelProvider` 会重新抛出保存失败，`submitModel` 在 await 成功后才重置；**不能把保存失败必定清空草稿写成已证实缺陷**。但关闭、切换旧子页面以及选择另一条编辑对象没有脏状态保护；需要集中处理离开行为。提交成功、随后列表刷新失败也需要单独表达，不能把网络操作的所有结果都压成一个全局字符串。

密钥留空保留原值的行为保留，并用可见辅助文案解释。未保存密钥只能保存在当前受控内存状态，不为记忆草稿写入 localStorage、URL、日志或报告；退出、注销及确认丢弃时清理。

### 新增模型

同一页用清晰的两个阶段组织，不强制所有编辑操作走向导：

1. 连接信息：协议、服务地址、API Key。必要说明靠近字段，检索失败不会清空连接信息。
2. 模型选择：获取后可搜索结果，每行“＋”立即保存该模型并变为“已添加”；列表和连接信息保留，允许连续添加。显示本次新建配置将使用的可见范围。服务不支持枚举时，允许直接手工输入 Model ID。

手工添加时名称默认取 Model ID，再允许改名；思考能力、上下文及协议兼容项放在有明确标题的次要设置区域。基本配置不依赖用户理解“触发水位”“系统消息布局”等内部术语。高级选项保留当前值，不通过重绘界面重置成默认值。

“获取模型列表”和“测试模型调用”分开命名；实际会向模型发请求的测试应提示可能产生调用用量，不把它称作只测网络连接。测试失败显示原因和重试入口，区分配置错误与网络／服务商响应。

首版继续使用现有每模型配置 API：共享本次新增流程中的输入，不代表后端已拥有独立的“连接”实体。**不得仅因 Base URL 和协议相同，就推断两条配置使用同一密钥，或让改一个模型隐式修改其他模型。** 若未来做真正共享连接，应单独设计连接 ID、凭据归属、模型引用和迁移，另立数据变更任务。

## 交互与实现优先级

### 第一阶段：结构与误操作保护

- 将 `SettingsModal` 的条件长页面改为设置外壳与分类内容，复用 `SettingsUI` 和现有业务组件。
- 模型／搜索列表与表单分离，加入稳定的当前编辑对象、dirty、saving、error 和 success 状态。不同类别的草稿按对象隔离，不能互相覆盖。
- 用一个离开守卫覆盖返回工作台、换类别、换编辑对象、取消和关闭；确认只在确有未保存输入时出现。整页刷新／关闭浏览器在脏状态下使用适用的浏览器保护机制。
- 当前模型和搜索列表的删除直接进入 API 调用链，增加对象明确的确认及删除后反馈；不扩大对其他管理操作的权限。
- 清除旧全局“完成”语义，增加本地错误与提交中状态。普通表单校验不需要全局错误横幅。
- 若实施前暂时保留模态，先补焦点循环、打开初始焦点、背景不可交互及关闭后返回；子菜单 Escape 不应连带误关设置。不能用 aria-modal 属性代替行为实现。

### 第二阶段：具体页面整理

- 用户：列表与创建分离，角色、状态和危险操作可识别；注册策略独立分组。
- 用量：日期／用户／模型筛选放统一工具栏，表格优先承担比较任务；统计卡保留有信息价值的少量指标。
- 日志：摘要可扫描，详情按需展开；管理员清空保留明确确认，不改变日志内容与脱敏机制。
- 扩展：空状态直接解释当前未安装，提供现有安装入口，不额外引入装饰性首页。

### 第三阶段：视觉及适配验收

保留字体、主题和强调色，统一页标题／分组标题／字段标签／说明层级；常规可读文本优先 13–14 px，避免把主要说明压到 10–11 px。容器减少到“外壳—内容—必要分组”，不为每行再包圆角大卡片。复用现有间距和动效 token，克制阴影和模糊；主要内容单一纵向滚动，避免多个垂直滚动区竞争。

逐页验证浅深色、760／1024／1440 px 视口、200% 缩放、长地址、长模型名、较多模型与键盘流程。实际对比度和点击目标需测量后判定，不凭截图直接声称满足 WCAG。

## 必须通过的验收任务

1. 从工作台进入设置可直接找到模型列表，换到联网／用户／日志无需返回混合首页；返回时原文稿、未保存文稿草稿、聊天草稿及 Agent 运行保持。
2. 一次输入连接信息、一次获取后连续添加三个模型，逐项结果清楚；失败可重试，已添加不重复创建，刷新后确已持久化。
3. 不支持模型列表枚举的服务仍可手工添加；编辑已有密钥留空不覆盖旧值。
4. 修改现有模型后换页、换对象、关闭，得到保留／确认丢弃的明确结果；保存失败保留输入；后台成功但列表刷新失败不诱导重复创建。
5. 保存慢请求时重复点击不会提交多份；错误与正在编辑的对象对应；关闭一个请求不能让迟到响应覆盖另一条模型的草稿。
6. 测试结果绑定本次连接／模型快照，修改关键参数后旧结果不继续显示为当前有效。测试不能默默修改保存值。
7. 删除确认准确指向目标对象；取消不改数据；当前默认模型删除后的前台选择与服务端规则一致。
8. 打开对话框焦点进入内部，Tab／Shift+Tab 不进入背景，Escape 层级正确，关闭后焦点返回触发位置。
9. 小屏／缩放后主要字段、保存和错误仍可达，无被裁切的关键操作；主题、滚动条、长列表与弹层定位均检查。
10. 回归现有模型快捷添加、供应商测试、上下文模板、可见性与用户隔离、统计／价格和日志流程；使用隔离数据库，不在手动实例改真实凭据做故障注入。

这是一份设计评审而非使用者研究结论。实施后应让用户实际完成“接入一个服务并添加多个模型”“修改已有模型”“查某次错误”三个任务，结合观察调整分组和默认入口。

## 来源与适用边界

以下均在本次研究中打开原文核对；没有以搜索引擎生成的概览代替原文。

1. [NN/g：Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)：主界面优先重要选项，较少使用的选项按需显示；入口应可发现、命名清楚，避免过深层级。本文据此建议把兼容参数后置，不把必要连接字段藏在提示中。
2. [IBM Carbon：Forms](https://www.carbondesignsystem.com/building-blocks/core/patterns/forms)：相关输入分组、符合逻辑的顺序、简明标签和内联错误、明确主次操作；一般优先单列表单，较复杂内容可用专用页面；不建议把长复杂表单塞进对话框并层层折叠。Carbon 的尺寸和输入数量建议属于其产品设计指南，不是所有产品的强制标准；本项目取原则，保留自己的视觉系统。
3. [W3C WAI-ARIA APG：Dialog (Modal) Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)：打开时移入焦点、Tab 循环、Escape 关闭、关闭后返回触发者，背景不可交互。此为对话框模式指导，不等于本次已执行完整 WCAG 合规审计。

## 代码定位

- `src/components/settings/SettingsModal.jsx`：混合首页、条件子视图、全局错误和仅关闭的“完成”。
- `src/components/settings/ModelProviderSettings.jsx`：常驻 380 px 表单、编辑对象切换、字段顺序、模型级操作。
- `src/components/settings/SearchProviderSettings.jsx`：同类常驻表单与过时文案。
- `src/components/settings/ModelProviderDiscoveryPanel.jsx`：保留逐项直接添加及反馈；重新组织获取、手工配置与测试含义。
- `src/hooks/useSettingsData.js`：写入、重载列表和全局错误；拆清提交成功与刷新失败的反馈契约。
- `src/motion/useDialogTransition.js`：处理 Escape 与关闭时序，没有焦点管理或 dirty 守卫；后续不应让动画 hook 同时承担表单状态职责。
- `src/components/settings/UsageDashboard.jsx`、`UserManagement.jsx`、`DiagnosticLogsView.jsx`：复用现有数据功能，调整为一致页面结构。

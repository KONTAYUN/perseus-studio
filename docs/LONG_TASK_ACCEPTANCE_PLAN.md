# Perseus 长任务验收方案（待用户批准）

> 此版已撤回，不作为执行依据。用户明确 Perseus 面向云端文稿工作台，要求使用 8080，且暂不使用 Skill。新版见 [WRITING_WORKSPACE_ACCEPTANCE_PLAN.md](WRITING_WORKSPACE_ACCEPTANCE_PLAN.md)。下文仅保留为前版设计记录，不执行其中代码开发、Skill 和破坏性故障项目。

设计日期：2026-10-22。当前状态：仅设计，未启动本方案的测试、模型调用或故障注入。

## 目标与结论边界

用一个真实多轮项目串联现有功能，再以受控故障验证错误路径。验收对象为执行时冻结的前后端版本及工作树差异摘要。通过表示本次场景有证据通过，不表示项目无缺陷。

最终分别交付：功能通过矩阵、失败复现步骤、脱敏证据、未覆盖项和建议修复顺序。本轮发现问题先留证，不修改产品代码；等用户看过结果再决定整改。

## 测试环境与边界

- 使用独立端口（优先 18080）、独立数据库、用户目录、管理员和两个普通测试用户；8080 的会话、工作区、配置和运行任务不用于测试。
- 使用现有构建的副本。需要编写的驱动、夹具和断言放入单独验收目录，不借机修复产品实现。
- 真实模型使用执行时可用、已配置的 Grok；在内存中复用授权凭据，不在提示、报告、截图或日志中输出密钥，不猜测固定模型名。
- 真实模型负责主要业务流程。模拟供应商只负责精确复现协议、限流、断流、坏参数等故障；两类证据分开记录。
- 搜索有可用凭据才做真实联网。缺少条件记为阻塞，模拟搜索仅证明适配流程，不能替代真实联网通过。
- 主流程命令默认关闭，验证关闭时的提示；代码实际运行由测试驱动独立校验。命令能力另开隔离验收进程，仅管理员显式启用 trusted_host，限定测试生成的可信 Node 脚本；该模式不是 OS 沙箱。普通用户始终验证拒绝执行。
- 不推送、不部署、不向外部发送消息、不安装来路不明的依赖；不删除用户数据。回收站、账号删除、Skill 删除只针对本次独立实例的夹具。
- 预计完整执行约 3–5 小时，取决于服务响应。首轮执行上限 5 小时、真实模型出站请求累计 150 次，包含重试和辅助标题请求；驱动记录计数并在到限时停止新请求、取消隔离运行，保留已有产物。单轮还遵守运行器预算，不绕过错误无限重试。未执行的阶段记为未执行。

## 业务主线：北辰项目资料工作台

让 Perseus 接手一份含混乱资料、已有代码和需求的迷你项目，完成资料归档、任务统计、外部资料研究和交付文档。实际操作通过浏览器界面进行；API、磁盘和数据库用于独立核验，不能直接替 Agent 写交付文件后宣称 Agent 成功。

### 初始夹具（批准后才创建）

| 路径 | 用途与预埋点 |
| --- | --- |
| `brief/需求.md` | 项目目标、目录约定和统计规则；要求提问确认归档目录名称 |
| `inbox/任务清单.json` | 12 条 UTF-8 任务记录，包含中文、空格、引号和特殊字符 |
| `inbox/会议记录 01.md`、`会议记录 02.md` | 重复标题、相近段落、任务引用，检验搜索后精确编辑 |
| `inbox/待归档 01.txt`、`待归档 02.txt`、`废稿.txt` | 批量整理、重命名、移动和回收站恢复 |
| `src/summary.mjs` | 已有错误：把 doing 统计为 done；要求先读再修 |
| `src/empty.mjs` | 空文件编辑，避免只覆盖有内容文件 |
| `docs/格式样本.md` | 标题、表格、任务项、嵌套列表、代码围栏、链接和带 span 的扩展语法 |
| `docs/扩展样本.md` | 当前编辑器不能安全往返的语法，验证原文保留及源码编辑路径 |
| `protected/不要修改.txt` | 唯一哨兵，要求保持原样，驱动保存哈希 |
| 上传附件 `补充需求.txt`、`参考布局.png` | 文本附件与图片附件路径；图片理解仅对支持视觉的模型断言 |

唯一统计规则：任务 ID 不重复，状态仅 todo/doing/done，优先级仅 P0/P1/P2；非法数据应报错，不能悄悄丢弃。按状态统计总数，P0 未完成数排除 done。

固定数据：T01–T12；todo 为 T01/T04/T07/T10/T12，doing 为 T02/T05/T08，done 为 T03/T06/T09/T11；T01–T04 为 P0，T05–T08 为 P1，其余为 P2。独立预期：总数 12，todo 5，doing 3，done 4，P0 未完成 3。验证器预期由测试驱动提前固定，不能从 Agent 生成的测试结果反推。

### 发给 Perseus 的首条业务指令

```text
请接手“北辰项目资料工作台”。先阅读 brief/需求.md、我上传的附件，并检查相关目录；不要根据文件名猜内容。

先给出实施计划。归档目录名称在需求中需要确认，请使用提问功能问我，得到回复后继续。

将 inbox 中待归档材料整理到确认的目录，保留原文件内容。修正 src/summary.mjs 的状态统计错误，补全空文件 src/empty.mjs 中的输入校验，添加必要的自动验证脚本。合法任务必须准确统计；重复 ID、未知状态、空清单分别有明确处理。尽量不引入第三方依赖。

输出 reports/任务统计.json 和 docs/交付说明.md。说明文档应有标题、统计表格、任务列表、链接和带语言标记的命令代码块。需要时使用已选择的 Skill。复杂工作可启动有明确目标和输出文件的后台任务，但你需要检查任务产物，不能只转述“已完成”。

protected/ 下的文件不能修改。现有文件先读后改；修改后重读验证。命令不可用时如实说明未执行，不能把编写测试当作测试通过。最终列出实际变更路径、验证结果及尚未完成的事项。
```

后续需求和干扰按下表在指定节点发送，不能首条消息全部透露，避免只测模型一次性照单生成。

## 阶段与通过标准

| 编号 / 阶段 | 操作 | 独立通过标准 |
| --- | --- | --- |
| A01 准备与基线 | 记录版本、工作树摘要、数据库与文件哈希、端口和资源基线；创建隔离账号和夹具 | 隔离实例就绪，8080 未被改变，测试标记及原始哈希可追踪 |
| A02 配置与模型 | 一次获取模型列表，连续加两个，连点、已添加、失败重试；编辑已有配置时 Key 留空复用；切换连接 | 列表/参数保留、无重复提交、已有默认不变、原配置不被覆盖、旧请求不污染新连接；无第二真实模型时真实业务只用可用模型，配置行为用模拟数据验证 |
| A03 计划、附件与提问 | 发首条指令；选择本次专用 Skill；Agent 询问目录后回复“归档资料” | 真实读取附件和相关文件；提问暂停处不提前按猜测归档；回复后使用指定目录。Skill 指令要求交付文档带固定标记，能看到 read_skill 与产物标记 |
| A04 搜索与文件管理 | Agent 搜索相关段落、批量移动待归档文件、重命名一份记录；浏览器手动上传/下载、树搜索、展开、排序、多选 | 文件树、API 和磁盘一致；移动内容哈希一致；同名冲突不覆盖。只有一份本次废稿进入回收站并可恢复，原文一致；独立夹具才能永久清理 |
| A05 编辑与统计 | 修已有文件、填空文件、新建脚本和报告；同一文件多次增量编辑；只展示补丁示例 | 12 条统计与固定预期逐项一致；非法输入测试有效；示例补丁不落盘；真实工具与落盘证据对应；protected 哨兵不变 |
| A06 多轮、队列与 steer | 运行中普通发送“交付说明增加维护建议”；另一轮 steer“统计增加 P0 未完成，但不要改状态定义”；等待 applied 再核验 | 普通跟进串行、不丢不重；steer 未 applied 前不伪装成已提交历史，应用后有实际结果；执行结束错过的 steer 能转为后续输入；快速双击发送不生成重复运行 |
| A07 会话上下文 | 运行中切到会话 B、返回 A；引用当前文件和两个不同编辑栏；另开独立会话做重命名、分支、重新生成和上下文压缩 | A 的事件不污染 B；引用指向正确路径；分支后消息属于新会话；压缩前后仍遵守 protected 限制和原统计规则；重新生成不得暗中回滚用户文件，若实现不能满足或语义不明确，记录问题 |
| A08 后台任务与联网 | 后台查阅两份官方资料，产出 `docs/可靠性调研.md`，包含来源和已核验建议；另启动可取消后台任务 | 有目标/步骤/日志；产物非空且来源可访问、内容相关；状态与真实产物对应。取消和失败不报成功；禁用 Skill 不可读取。无真实搜索条件明确阻塞 |
| A09 富文本与聊天呈现 | 检查聊天 Markdown、代码语言及复制；编辑文档选区加粗/链接、六点段落菜单、任务项、表格、撤销；模式切换并保存、刷新重开 | 复制内容逐字一致；打开文档不触发写入；简单格式保存后正确；span、代码、链接和非目标段落保留；不支持的扩展语法不被静默改写；恶意链接/HTML 不执行 |
| A10 格式修复与保存冲突 | 源码破坏明确可检测的围栏；点黄色提示，先取消再确认；另在保存前由驱动改同文件 | 取消不发消息；确认后先成功保存再向当前 Agent 发正确路径请求，保留输入框草稿；冲突/保存失败/文件切换不发送错误修复；用户新内容不被自动保存覆盖 |
| A11 变更查看和撤销 | 查看本次 patch 修改前与当前内容；对专用文件撤销，刷新后再次请求撤销；再制造人工后改冲突 | 撤销对应单处变更且幂等，不误撤销其他文件；冲突时保留人工内容并说明原因；新文件撤销进入回收站；不把界面变更预览当作全轮快照 |
| A12 命令、角色和隔离 | 验证默认禁用；另开 trusted_host 测试进程运行可信脚本的成功、非零退出、超时与取消；普通用户访问管理员功能和其他用户资源 | 失败/超时不能记为通过；默认禁用及非管理员不能绕过；跨用户文件/会话/任务/配置/诊断访问拒绝，无副作用；越界路径拒绝。宿主命令不宣称有 OS 隔离 |
| A13 故障与恢复 | 按故障矩阵逐项执行，每次还原干净夹具 | 有确定触发点、原始失败证据及磁盘/事件/状态核对，不靠最终回复自证 |
| A14 UI、用量与收尾 | 深浅色、减少动态效果、连续布局切换/开关设置、长消息滚动；诊断与用量查看/导出；关掉测试服务后重新开库 | 无阻断功能的遮挡、卡死、异常滚动或页面异常；菜单和工具条可键盘操作；用量去重、不把未知价格显示为真实 0 元；导出脱敏；持久记录可打开，原数据基线一致 |

## 受控故障矩阵

每项使用独立夹具或快照。模拟供应商必须确实返回指定故障，不能通过替换前端文本假装发生故障。崩溃只影响测试进程。

| 编号 | 注入点 | 必须观察到的行为 |
| --- | --- | --- |
| F01 | 模型 429 + Retry-After、短暂 5xx 后成功 | 不提前重试；遵守预算，界面有状态，成功后无重复工具副作用 |
| F02 | 错误 Key / 401、持续失败、非法 JSON | 错误原因可定位；不会永久转圈或无限回退；不可把失败当完成 |
| F03 | SSE 在工具成功落盘后断开、刷新页面、从事件游标补读 | 文件/消息/工具事件最终一致，已经确认的工具不再重做；最终快照不残留旧草稿 |
| F04 | 接受请求后故意丢响应，用户点停止；重复提交同一幂等键 | 后端已登记的运行仍被取消；同一请求不产生两套副作用 |
| F05 | 工具读取后、patch 前由驱动更新文件；另提交不匹配/歧义 patch | 冲突不覆盖，失败不修改文件；Agent 重新读后再决定下一步，不能强行模糊落盘 |
| F06 | 明确非法的嵌套参数、路径越界、重复工具错误 | 参数在副作用前拒绝；运行有界结束或请求协助，错误身份与诊断对应 |
| F07 | 工具完成事件持久化点用独立 SQLite trigger 制造失败 | 后续工具停止，保留首个已发生副作用的证据，不把存储故障写成用户主动取消 |
| F08 | patch 的已知阶段进程退出，再启动同一测试实例 | 按当前恢复契约恢复或显式阻塞；不无条件整轮重跑；用户后续修改保留；二次恢复幂等 |
| F09 | 两会话并行、取消后台任务后重启、删除测试会话时仍有活动任务 | 无跨会话污染；取消不复活；删除及任务状态满足现有生命周期契约，不出现孤儿执行 |
| F10 | 请求/时间预算耗尽、重复无进展读取 | 有界终止并说明已有结果和未完成项；不无穷自动继续 |

F07/F08 若没有稳定可控的浏览器触发点，使用真实后端集成/子进程测试，并在报告明确“API/进程级”，不能记成浏览器已验证。重启前后的对比只要求符合声明的恢复契约，不凭空要求 exactly-once 或断电 ACID。

## 独立验证与证据

1. 提前固定统计 oracle、输入边界及保护文件哈希，使用不依赖 Agent 测试代码的验证器；至少一项负例能打败初始错误实现。
2. 每个 case 保存运行 ID、会话 ID、工具调用 ID、事件序列范围、执行版本和耗时。只保留必要脱敏日志，不保存凭据、完整请求头或真实用户正文。
3. 核对 UI、API、文件系统及数据库，特别区分“请求已接受”“工具已成功”“内容已落盘”“用户任务已完成”。异步状态使用有上限的条件等待，不以固定 sleep 冒充成功。
4. 关键编辑与跨会话时序使用新夹具重复两次；重复失败、重试次数及首次失败均保留，不能只取最后一次成功结果。
5. 故障发现后立即保存最小复现和数据副作用范围。数据丢失、越权、错误执行、无法取消或无限请求出现时，停止相关测试进程；无依赖的其他测试可继续，依赖项标记阻塞。
6. 浏览器主线完成后再运行相关既有单测、后端回归和 UI/结构/构建门禁；记录本次结果，不沿用历史通过数。不具备 Linux、Docker、真实断电条件的项目明确未测试。

## 交付与判定

结果报告拟保存为 `docs/LONG_TASK_ACCEPTANCE_RESULTS.md`，证据放 `_local_artifacts/long-task-acceptance/<run-id>/`。报告包括每项 PASS / FAIL / BLOCKED / NOT RUN、首次失败、重试、影响、复现和优先级；提供真实模型、模拟故障和既有回归三类证据的分列统计。

通过条件：A01–A14 的适用断言全部有证据通过，F01–F10 无未解释失败，保护数据和跨用户隔离无破坏，关键路径重复稳定。缺少供应商/搜索/视觉能力等只记阻塞，不计通过。真实模型效果不足、工具/前端/后端错误、外部服务不可用分别归因。

批准本方案后再准备环境并执行；本轮交付测试结果和问题清单，不自动进入产品修复。

# Perseus Studio 项目诊断与优化记录

日期：2026-10-20。检查起点：`master` / `fa641a6`。本轮修改保留在工作树，未提交、推送或部署。

## 结论

Agent 无法编辑的主要根因在工具协议层：多数模型看不到可调用的 `apply_workspace_patch`，运行时还拒绝普通供应商返回的 JSON 编辑调用。提示词要求正文补丁，但模型、工具声明和执行器之间的约定不一致。这是跨模型的共同故障，不能靠换模型解决。

已恢复两个协议默认可用的 JSON 编辑工具，同时保留正文补丁兼容通道。通过真实 HTTP 服务和 Chrome 验证：输入用户指令后，Agent 能读取文件、调用补丁工具、实际修改磁盘、刷新已打开的编辑器。

使用用户提供的 relay 接口额外完成两款 Grok 的真实在线浏览器测试：`grok-4.20-0309-non-reasoning` 和 `grok-4.3` 均成功修改普通文件、向已有空文件写入内容并创建新文件，任务状态为 `succeeded`，磁盘内容与编辑器刷新均通过断言。测试同时定位并修复了单 system 消息兼容与补丁空白分隔兼容问题。

本轮还修复了保存覆盖、标签页同步、路径校验、后台工具加载和资源限制等问题。检查覆盖了主要请求链路与现有测试，不能证明不存在其他缺陷；未完成的部署级问题见下文。

## 已修复问题与证据

| 问题 | 原因或影响 | 本轮处理与验证 |
|---|---|---|
| 默认模型没有编辑工具 | manifest 隐藏 patch；OpenAI 绑定域名/开关；Anthropic 缺少 schema；运行时拒绝调用 | 统一声明、参数校验、提示词和执行器；两个协议分别通过磁盘写入回归和浏览器聊天回归 |
| Grok 完整 Agent 请求返回 400 | relay 接口拒绝多条 system 消息，普通聊天正常却无法进入工具循环 | 对照实验保留全部工具仍成功、去掉工具仍失败，仅合并 system 即恢复；为 Grok 在发送前无损合并 system，保留上下文、图片与工具消息顺序；两个真实型号全部 13 次模型请求均为 200 |
| 多文件补丁被空白分隔行阻断 | 模型在文件操作段落间加入裸换行，解析器将其视为无前缀内容 | 仅容忍操作/hunk 边界的空白分隔；文件内真实空行仍须显式前缀，歧义内容仍拒绝；实际三文件写入和回归测试通过 |
| 编辑入口提示互相矛盾 | 读取结果与恢复提示仍要求正文补丁；manifest 同时将两个通道标为首选 | JSON 工具可用时统一优先 `apply_workspace_patch.patch`，正文补丁保留为兼容回退 |
| 后台任务缺少可加载工具 | 后台关闭 loader，却只初始化 workspace | 后台预加载允许的工具组；保留禁止递归任务；回归覆盖命令、搜索、Skill 可见性 |
| 已存在的空文件不能插入 | 补丁匹配器要求旧内容或上下文 | 支持单 hunk 的空文件插入；检验实际写入内容 |
| 引用文件后不能创建输出或重命名 | 范围校验把新目的地当成受限既有文件 | 约束被修改的源文件；允许不覆盖既有文件的新目的地；仍拒绝未选中的既有源文件 |
| 多文件补丁丢失路径变化 | 返回值缺少逐项移动、回收站映射 | 返回 `moved`，供既有 ToolEvent/SSE 同步流程使用；回归覆盖 rename + delete |
| 多标签页只刷新一个 | 使用 `find` 选首个非当前文件 | 刷新全部受影响标签页；回归同时修改多个文件 |
| 文件哈希串用 | 所有变动路径共用主文件/文件夹 hash | 按精确路径分配元数据；读取结果的实际 hash 优先；目录 hash 不传给子文件 |
| 异步读取覆盖用户输入 | 响应返回后未检查当前内容或 dirty 状态 | 活动文件和非活动标签页均保留等待期间的新输入，并标记冲突；切换标签页时防止错误激活 |
| 混合补丁刷新错误 | 移动一个文件时直接跳过同事件里的其他修改；删除后仍读取原路径 | 同时处理移动和其他修改；删除路径关闭对应标签页；纯函数与动作测试覆盖 |
| 自动保存覆盖 AI 修改 | 写接口没有版本条件；保存响应还覆盖晚输入 | 增加可选 `expected_hash`，同一服务内加锁比较并写入，冲突返回 409；保存响应只更新已保存基线 |
| “保留本地”立即自动覆盖 | 清除冲突会重新启动自动保存；界面没有对应手动保存入口 | 保持自动保存暂停，明确显示“保存本地版本”，由第二次明确操作写回；真实浏览器验证双方版本得到保留 |
| 并发创建/读改写竞争 | 检查、读取和写入之间没有统一内容锁 | 创建、覆盖、追加、替换等内容操作在同一 per-user 服务锁内执行；并发 CAS 只有一个请求成功 |
| 补丁别名与无效目标 | `a.md` 和 `./a.md` 被当成不同文件；目标读取失败被当成不存在 | 规范化并验证路径；使用 stat 区分缺失和其他错误；先拒绝重复操作；更新和回滚使用内容哈希条件 |
| Windows 名称校验绕过 | `Clean` 返回反斜杠，后续只检查正斜杠 | 统一路径分隔符；拒绝目录型 leaf 参数；Windows 测试复现并验证 |
| 链接访问越界 | 仅做词法路径包含检查 | 拒绝路径中的符号链接、junction 和其他特殊文件；搜索、命令快照跳过链接/特殊文件；外部目录链接测试验证 |
| 命令输出占满内存 | 运行结束才截断无界 Buffer | 采集期间限制 stdout/stderr 各 80,000 bytes，同时持续排空管道；20 MB 输出回归验证上限；WaitDelay 防继承管道无限等待 |
| 命令快照读取整文件 | 对每个文件使用 ReadFile 哈希 | 改为流式哈希，避免内存峰值随单文件大小增长 |
| 任意跨站来源被信任 | 无条件反射 Origin 并允许凭证 | 默认同 host；额外来源必须配置精确白名单；拒绝请求在进入业务处理前完成；回归覆盖不可信、同 host、显式白名单 |
| 首次注册权限竞争 | 多请求都可能看到用户数量为 0 | 单服务注册互斥；并发请求测试仅产生一个首次管理员 |
| 上传上限失效、临时文件未清理 | multipart 参数只是内存阈值；ReadAll 无总量限制 | 文件上限 64 MiB，总请求 65 MiB，超限 413；释放 multipart 临时文件 |
| HTTP 连接占用 | 缺少请求头/空闲超时 | 增加 ReadHeaderTimeout 和 IdleTimeout；不设置会截断长 SSE 的全局 WriteTimeout |
| Compose 配置不生效 | 未转发示例中的 worker、管理员等变量 | 补齐任务、关闭超时、首次管理员和 CORS 变量 |
| 依赖与回归门禁 | Vite 5 依赖告警；原测试甚至断言编辑工具应隐藏；CI 未跑浏览器编辑 | 升级 Vite 7.3.7 及可兼容依赖；明确 Node engine；CI/Docker 使用 Node 22、Go 1.27；加入独立 E2E 门禁，镜像构建依赖其通过 |

## 未完成的部署级整改

### P0：命令执行不是多租户安全沙箱

`cwd` 和危险命令字符串拦截无法阻止任意脚本读取宿主文件、访问其他用户目录、网络或进程环境。路径链接校验只强化文件 API，不会把 shell 变成沙箱。Docker 镜像当前仍以 root 运行；单个共享容器也不能隔离容器内各用户。

整改方案：把命令交给独立 worker；每次执行只挂载当前工作区，使用非 root UID、只读根目录、CPU/内存/PID/时间限制、独立进程组以及受控网络；不挂载数据库、配置和其他用户目录。外部不可信多用户部署应先完成这一项。本轮没有把 denylist 当作隔离修复，也没有声称进程树取消已完整解决。

### P1：多文件事务与进程外竞争

本轮锁与哈希比较保护单进程内容写入，补丁失败时仍采用尽力回滚。重命名、回收站操作、外部 shell、其他服务进程和崩溃恢复尚不共享完整事务。后续优化已汇总返回回滚失败，并增加逐文件变更验证，见 PROJECT_OPTIMIZATION.md。文件 API 的检查与实际系统调用之间仍存在链接替换窗口；hardlink 也未实现完整隔离。

整改方案：以工作区操作日志统一内容写入、移动、删除；先暂存和校验，记录提交/回滚状态，重启后恢复未完成事务。生产服务保持单实例写入，命令执行纳入同一调度器。需要强隔离时使用 OS 支持的根目录文件句柄操作或隔离 worker，不能仅增加字符串检查。

### P1：剩余构建依赖告警

剩余告警经 `tailwindcss → chokidar / fast-glob / micromatch / braces` 和 `postcss-nested → postcss-selector-parser` 传播。当前 registry 的 braces 3 分支没有可直接替换的修复版；audit 推荐 Tailwind 4，属于破坏性迁移。本轮未强制升级并冒险改变现有 CSS 行为。

整改方案：单独迁移 Tailwind 4，配合浅色/深色和主要交互页面截图验证；构建环境只处理可信输入。后续锁定安全的依赖版本，避免把开发依赖告警等同于浏览器生产包运行漏洞，也不能完全忽略构建侧风险。

### P2：需要更长周期验证的区域

本轮完成两款真实 Grok 的短任务功能验证，未做真实供应商长期稳定性、长会话/恢复/队列持续压力测试、所有附件格式模糊测试、跨平台进程树取消测试或多实例注册竞争验证。已增加显式 opt-in 的在线编辑测试，后续可扩展为夜间兼容性检查；下一阶段建议建立任务恢复/取消压力场景及上传/补丁 fuzz 测试。管理员注册锁也需随多实例架构迁移到数据库事务。

## 维护约定

编辑工具的可见性、schema、manifest、提示词和运行时权限应共同变更，并通过“用户指令最终改变磁盘”的回归确认。仅检查提示词文本或声称已有工具，不能证明编辑链路可用。历史结构自评分不能替代行为与安全验证。
